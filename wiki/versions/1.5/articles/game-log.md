Every saved world keeps a game log: one timestamped line for each thing the game logs, in the order it happened. It is stored with the world in the browser, so it is there again when you load the world, and it is deleted with the world. Worlds that aren't saved (the title screen's world) keep no log.

## What a line says

```
2026-10-17 16:55:13.123  Day 3 07:15  chunk 1d 02:10  INFO   trade  Village of Ohope: Aroha Parata (Farmer) traded with ...
```

- **System time**: the date and time on your computer, to the millisecond.
- **Game time**: the game day and the time of day.
- **Chunk time**: how long the chunk where it happened has been loaded over the whole game, in game days, hours and minutes. Like a village's age, it counts only game time while the chunk is loaded. Lines with no place show `-`.
- **Level**: ERROR, WARN, INFO or DEBUG.
- **Kind** and, for village events, the village's name.

The first line of the file names the world, its seed, the game version and the commit it was started with. When you load the world with a different version or commit, a line says what changed.

## Levels

- **ERROR**: a villager's task cut off when its village unloaded (see [[page:village-loading]]), a villager or golem stuck in one place for 30 seconds of trying to walk (short pauses between tries count too), or fallen into a well it has to climb out of (kind *move*), a slash command that failed with an unexpected error (kind *command*), a message from the page that the simulation could not read or take (kind *protocol*, once per kind of message: the message is dropped and the world plays on), the browser taking away the 3D view's graphics context, which leaves the screen black until it gives it back (kind *graphics*, with how many meshes and textures the view held), and any error the game caught or didn't catch.
- **WARN**: warnings the game prints, a session that ended without unloading the world (the tab was closed or the browser stopped), and the game's files changing on disk while it runs (reload to play the new version).
- **INFO**: the world loading and unloading, whether the world's block data is in shared memory (it is when the game is started with `./run.sh`, which serves it with the headers browsers need; opened from its file it isn't, and the game plays the same), version changes, a stuck villager or golem getting moving again, climbing out of a well, a golem leaving a monster it found no way to, and a seller that waited 8 seconds for a buyer and carried on (kind *move*), the world's game options as it opens and every change to them, with the monsters that left because their kind was turned off (kind *options*), each village going past your view distance into coarse mode and back to full detail when the *Far villages* option is *Coarse* (kind *coarse*, see [[page:village-loading]]), the [[page:state-hash]] as each game day starts (kind *State hash*), the [[page:performance-meter]] turning on and off (kind *perf*), the graphics context coming back, after which the distant terrain and the far chunks are built again (kind *graphics*), villages joining or leaving the simulated set for the [[page:village-loading|simulation budget]] and changes to the budget (kind *budget*), recording and replaying a session of your actions, and an edit of yours that came too late because something else changed the block first (kind *Request queue*, see [[page:state-hash]]), each generated sign (a village sign, a signpost) as it comes into the world (kind *signs*), a drag-split over inventory slots that no longer took the held item when it arrived (a shift-click had just filled one), so the items were split over the slots that still did (kind *inventory*), a summary once a game hour of the regions simulated and the time each part of a tick took, while the F3 overlay or the debug screen is open (kind *Regions*), the debug screen's alerts reaching the game and each alert that fires (kind *alerts*), and every entry of every village's log: trades, beds, births, deaths, jobs, building and the rest. With the simulation on its own thread (see [[page:performance-meter]]), INFO lines (kind *worker*) say where the simulation runs (the world server, a worker, or the page) and how long a world took to start there, and note a change to the pause menu's *Simulation* setting; a WARN says why a host you asked for couldn't run, and an ERROR gives the error if it ever stops. INFO lines (kind *workers*) say how many [[page:several-cores|region workers]] a world got, when they are ready, and when the thinking is split over them or goes back to one; an ERROR says if one crashed or their copies of the world stopped matching. INFO lines (kind *clusters*) say when the [[page:several-cores|cluster tick]] is turned on or off, and give a summary of the clusters once a game hour while the F3 overlay or the debug screen is open, and note the first block tick that waited for a meeting because it was at a border; an ERROR names a cluster whose tick failed, or animals (pens, bees) that another worker sent for a village or home this worker doesn't have. With clusters on, an INFO line (kind *wildlife*) notes a wild mob that wandered into another cluster's unloaded chunk and waits there for the next meeting, and an ERROR (kind *boats*) a boat handed over at a meeting whose passenger didn't come with it. While the debug screen is open, INFO lines (kind *threads*) name the simulation's threads whenever they change, and once a game hour give how busy each was over the last minute (see [[page:several-cores]]). With the [[page:world-server]], the server keeps the log; INFO lines (kind *server*) say when the world paused and saved because its page closed and when a page picked it up again, a WARN notes a second page that was turned away and a page whose connection was lost without closing, and the page logs an ERROR (and shows the log's last lines) if the server stops. Saving has its own kind, *save* (see [[page:saving]]): a DEBUG line for each save with how long it took, an ERROR when a save fails (the previous save is kept) or an import is refused, and INFO lines for exporting, importing and copying worlds to the server.
- **DEBUG**: each job's own record of what it decided and did, and births and children growing up.

A world keeps its newest 100,000 lines, about two weeks of game days with four villages loaded.

## Reading it

Start the game with `./run.sh` and open the debug screen. The **Game log** button at the top (it counts the errors) opens the log above everything else, newest first, and updates live. Filter it by level (DEBUG starts hidden), by kind of event, by village and by villager type, or search it. **Copy** puts the lines shown by the filters on the clipboard, oldest first, under the header; **Download** saves the same as a `.log` file named after the world.

The commit is known only when the game is served by `./run.sh`; otherwise the log says it is unknown.
